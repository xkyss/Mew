# v0.1.4 活动栏上下文导航规格

Status: ready-for-agent

> 版本：v0.1.4
> 对应 ADR：`docs/adr/000104-01-activity-context-navigation.md`

## Problem Statement

Workbench 已能分别注册活动栏、侧边栏与编辑器区，但三者没有明确且统一的联动模型。活动栏项可任意绑定点击动作，侧边栏的显示逻辑只面向首个工具视图，导致 Launcher 需要手工协调“启动”和“设置”上下文；用户也无法可靠地从当前编辑器文档回到它的侧边栏对象。

## Solution

Workbench 提供由活动栏上下文驱动的三栏导航：每个活动栏项唯一对应一个侧边栏视图，活动栏只用于切换该上下文；侧边栏中的可编辑对象单击后在编辑器区打开或激活唯一文档；编辑器区保持独立，不自动反向改变导航。用户可从编辑器标签显式执行“在侧边栏定位”回到所属对象。

## User Stories

1. As a Workbench 用户, I want 每个活动栏项对应唯一的侧边栏视图, so that 我清楚图标会打开什么内容。
2. As a Workbench 用户, I want 活动栏仅承担导航, so that 我不会把即时动作误解为一个可恢复的工作台上下文。
3. As a Workbench 用户, I want 点击非当前活动栏项时显示其侧边栏视图, so that 我能在工具上下文之间直接切换。
4. As a Workbench 用户, I want 重复点击当前活动栏项时收起侧边栏, so that 我能为编辑器区腾出空间。
5. As a Workbench 用户, I want 在侧边栏收起后再次点击当前活动栏项时恢复该视图, so that 我不必先切换到其他工具才能返回。
6. As a Workbench 用户, I want 侧边栏收起后仍看到当前活动栏项的选中样式, so that 我知道自己处于哪个活动栏上下文。
7. As a Workbench 用户, I want 活动栏切换不改变已打开或当前激活的编辑器文档, so that 我浏览导航时不会中断正在进行的工作。
8. As a Launcher 用户, I want 单击侧边栏中的可编辑对象时打开或激活其详情文档, so that 侧边栏可用于定位，编辑器区可用于编辑。
9. As a Launcher 用户, I want 同一启动项只对应一个可激活的详情文档, so that 我不会得到重复标签或相互冲突的编辑状态。
10. As a Workbench 用户, I want 切换编辑器标签时不自动切换活动栏或侧边栏, so that 我不会丢失正在浏览的分类与筛选条件。
11. As a Workbench 用户, I want 关闭编辑器标签时不改变侧边栏选择或活动栏上下文, so that 关闭文档不会造成意外导航。
12. As a Workbench 用户, I want 从编辑器标签的右键菜单执行“在侧边栏定位”, so that 我能主动回到当前文档的来源对象。
13. As a Workbench 用户, I want 应用能为“在侧边栏定位”绑定快捷键, so that 常用反向定位可以不经鼠标完成。
14. As a Workbench 用户, I want 执行“在侧边栏定位”时切换到所属活动栏上下文、展开侧边栏并选中对应对象, so that 我看到完整且可继续操作的导航位置。
15. As a Workbench 用户, I want 无所属活动栏上下文的文档不提供“在侧边栏定位”, so that 系统不会捏造不真实的导航关系。
16. As a Workbench 用户, I want 重启后恢复上次的活动栏上下文和侧边栏显隐, so that 我的工作台布局保持连续。
17. As a Workbench 用户, I want 已不存在的恢复目标自动回退到第一个已注册活动栏项, so that 应用升级后仍可正常打开。
18. As a Workbench 用户, I want 侧边栏筛选在同次运行中切换上下文后保留, so that 我来回查看时不会重复输入。
19. As a Workbench 用户, I want 重启工作台后不恢复侧边栏筛选条件, so that 我从干净的浏览状态开始。

## Implementation Decisions

- Workbench 引入活动栏上下文模型，显式维护当前活动栏项、其唯一侧边栏视图及侧边栏显隐状态。
- 活动栏注册必须和侧边栏视图一对一配对；缺失对应项、重复对应或把活动栏项作为独立动作的声明均为无效配置。
- 选择非当前活动栏项时，激活对应工具视图并显示侧边栏；侧边栏显示时重复选择当前项会收起侧边栏；侧边栏已收起时选择当前项会显示其视图。
- 当前活动栏项以持续选中样式显示，侧边栏收起不改变该样式与上下文。
- 侧边栏到编辑器区采用单向“打开或激活”：同一可编辑对象在编辑器区具有唯一文档身份。活动栏切换、编辑器切换与编辑器关闭均不自动反向改变导航。
- 为具有活动栏上下文归属的编辑器文档提供“在侧边栏定位”命令。该命令从编辑器标签右键菜单提供，并允许应用注册快捷键；执行后切换上下文、显示侧边栏并选中对象。没有归属的文档不暴露该命令。
- 布局持久化除现有停靠布局外，保存活动栏当前项与侧边栏显隐。恢复目标失效时选择第一个已注册项。
- 侧边栏筛选是运行期状态，按活动栏上下文分别保留；不写入布局持久化数据。
- Launcher 改为使用 Workbench 的活动栏上下文能力实现“启动”和“设置”切换，移除由应用回调手工管理的同类导航状态。
- 实现遵守 ADR `000104-01` 与既有 MewDock、编译期组合及 NativeAOT 决策。

## Testing Decisions

- 最高且唯一的验收缝是 Launcher App 本身，沿用现有 Workbench/Launcher 功能通过示例工具验收的约定；不新建独立测试项目。
- 好测试只观察可见行为与持久化结果，不断言内部状态字段或 MewDock 调用顺序。
- 手工冒烟应覆盖：启动项与设置项的一对一切换；重复点击收起与恢复；当前项选中样式；活动栏切换不扰动详情文档；编辑器切换/关闭不反向导航；右键“在侧边栏定位”的成功与无归属文档不可用；筛选跨上下文保留、重启清空；上下文和侧边栏显隐重启恢复；失效恢复项的安全回退。
- 验收同时确认 Launcher 中的启动项详情仍保持单一文档，并验证现有分类树、搜索过滤与启动行为未回归。

## Out of Scope

- 活动栏中承载无侧边栏对应关系的即时动作。
- 编辑器标签切换或关闭时的自动反向同步。
- 为无所属活动栏上下文的文档编造定位目标。
- 全局持久化侧边栏筛选条件。
- 命令面板、快捷键自定义界面或运行时插件机制；本功能仅支持应用在编译期注册定位快捷键。
- 修改 MewDock 的停靠、标签或布局引擎能力。

## Further Notes

- 领域术语见根目录 `CONTEXT.md`，包括“活动栏上下文”“侧边栏筛选”及“在侧边栏定位当前文档”。
- 三栏导航的决策原因、替代方案和后果见 ADR `000104-01-activity-context-navigation.md`。
