# v0.1.3 Launcher 重新规划:分类树与双上下文布局

Status: ready-for-agent

> 版本:v0.1.3(本 spec 即该版本的 PRD,存于 issue tracker)
> 对应 ADR:`docs/adr/000103-01-category-tree-first-class.md`
> 术语见 `CONTEXT.md`(「分类」「未分类」为本次新增,「启动项」定义已更新)

## Problem Statement

v0.1.2 的 Launcher 主窗口沿用 v0.1.1 布局:活动栏按分类堆图标(分类越多越挤)、侧边栏平铺当前分类列表、编辑器区只有一个详情表单;数据模型是平铺数组,分类是单字段自由字符串——无法多级组织、无法表达空分类与顺序,重命名分类要改每个启动项。功能都在,但组织方式撑不起「分类管理」这个核心诉求,需要按「活动栏 = 上下文切换器、侧边栏 = 导航、编辑器区 = 内容」的结构重新规划。

## Solution

- **布局重构**:活动栏只剩「启动」「设置」两个上下文切换器(设置在最底部)。
  - **启动上下文**:侧边栏 = 多级分类树(「全部」置顶、用户分类、「未分类」收尾,顶部可搜索分类);编辑器区 = 「启动项列表」(卡片默认 ⇄ 列表切换,顶部搜索启动项 + 新增)+「启动项详情」(单击打开)。
  - **设置上下文**:侧边栏 = 设置分类(外观 / 热键 / 数据);编辑器区 = 对应设置内容。
- **数据模型重构**:`launcher.json` 改为 `{ categories, items }`;分类树是一等公民,启动项引用分类节点 id(全局唯一 slug),移动/重命名分类不影响启动项;旧数据首启自动迁移。

## User Stories

### 启动上下文

1. As 用户, I want 活动栏只保留「启动」「设置」两个入口(设置在最底), so that 界面不随分类数量膨胀。
2. As 用户, I want 侧边栏以分类树导航(「全部」/ 多级分类 /「未分类」), so that 按组织方式浏览启动项。
3. As 用户, I want 侧边栏顶部可搜索分类(节点名过滤), so that 分类很多时能快速定位。
4. As 用户, I want 选中分类后编辑器区显示该分类(含子孙)的全部启动项, so that 一个分类一个总览。
5. As 用户, I want 列表以卡片(默认)或列表两种形态展示并可切换、偏好保留, so that 浏览与密集管理各取所需。
6. As 用户, I want 单击卡片/行打开详情、双击启动、右键菜单(编辑/删除), so that 手势统一且不误触。
7. As 用户, I want 列表文档顶部可搜索当前分类下启动项、可新增启动项(自动归入当前分类), so that 创建与过滤都在内容区完成。
8. As 用户, I want 详情表单的「分类」字段为树形选择器, so that 归属一目了然。
9. As 用户, I want 分类树节点右键可新建子分类 / 重命名 / 删除, so that 分类可自由组织(「全部」「未分类」除外)。
10. As 用户, I want 删除分类时弹确认(提示将删除 N 个启动项)并连根删(子分类与项全删), so that 误删有缓冲、语义可预测。
11. As 用户, I want 切换「启动 / 设置」上下文时各自状态保留(选中分类、搜索词、形态、打开的标签), so that 查看设置后回来编辑不中断。
12. As 用户, I want 底部面板启动日志与状态栏(最近结果 + 呼出热键)保留, so that 启动失败可排查。

### 设置上下文

13. As 用户, I want 设置侧边栏分「外观 / 热键 / 数据」三分类, so that 设置也有导航。
14. As 用户, I want 外观 = 主题三选一(即时生效并持久化)、热键 = 呼出热键(捕获改绑 + 冲突提示)、数据 = 文件路径(打开所在文件夹), so that 与 v0.1.2 行为一致、只是换了位置。

### 数据与迁移

15. As 用户, I want 启动项数据自动迁移到新结构(旧分类文本 → 根级分类,「默认」→ 未分类), so that 升级不丢数据。
16. As 用户, I want 手写 JSON 仍可读可 diff(categories 树 + items 引用), so that 备份 / diff 习惯保持。

## Implementation Decisions

- **模块划分不变**:`Mew.Workbench`(框架库,不感知分类概念)/ `Mew.Launcher`(示例 App)。活动栏固定两图标、分类树、卡片网格均在 Launcher 侧组装。
- **launcher.json 新结构**:
  ```json
  {
    "categories": [
      { "id": "games", "name": "游戏", "children": [ { "id": "games-steam", "name": "Steam" } ] }
    ],
    "items": [
      { "id": "steam", "name": "Steam", "command": "steam", "categoryId": "games-steam" }
    ]
  }
  ```
  - 分类节点:`id`(全局唯一 slug,创建时自动生成如 `cat-1a2b`,手写 JSON 可自定义为可读 slug)+ `name` + `children`。
  - `categoryId` 可空(未分类);悬空引用(指向已删分类)Load 时归一「未分类」。
  - 「全部」「未分类」不落盘,是聚合视图。
- **迁移**:`LauncherStore` 检测旧格式(根为数组)→ 自动转换(旧 `category` 文本 → 根级分类,「默认」→ 未分类),无备份(用户决定)。
- **聚合语义**:选中分类 = 该节点子树所有项;「全部」= 所有分类 + 未分类。
- **删除分类**:右键 → 确认框(提示删除 N 个项)→ 连根删。
- **上下文状态**:内存态(选中分类 / 搜索词 / 形态 / 打开的详情标签)在活动栏切换间保留;形态偏好(卡片 / 列表)持久化到 `settings.json`。
- **浮层 / 每项热键 / 托盘 / 标题栏菜单**:不变;标题栏齿轮与 File→设置 改切到「设置」上下文。
- **搜索**:侧边栏 = 分类名子串过滤(树节点过滤);列表顶部 = 启动项过滤(复用 `LauncherSearch` 名称/命令匹配)。
- **卡片**:等宽网格(大图标 + 名称,悬停显示命令),双击启动 / 单击开详情 / 右键菜单;**列表**:行 = 图标 + 名称 + 命令 + 行尾「启动」按钮,同一套手势。

## Testing Decisions

- **测试缝(本次新增)**:`Mew.Launcher.Tests` 首个测试项目——只测 Launcher 的**纯逻辑层**(迁移、分类树聚合、悬空归一),不测 UI;UI 行为仍走手工冒烟。保持"唯一纯逻辑缝"原则,不铺开。这是 v0.1.2 spec 预留的"更重纯逻辑时评估补测"触发点:无备份迁移是"出错即丢数据"的高危逻辑,值得自动化回归。
- **好测试的标准**:只验证外部可观察行为(给定输入 JSON → 迁移后结构与内容正确;给定树与项 → 聚合结果正确;悬空 id → 归「未分类」),不测实现细节。
- **被测纯逻辑**:
  - 迁移:旧平铺数组(含中文分类、缺失可选字段、空列表)→ 新 `{ categories, items }` 结构,旧「默认」→ 未分类,项不丢。
  - 聚合:选中分类返回子树所有项;「全部」= 所有分类 + 未分类。
  - 悬空归一:`categoryId` 指向不存在的分类 → Load 后归「未分类」。
- **手工冒烟清单**:
  1. 活动栏仅「启动」「设置」(设置在最底);切换上下文侧边栏/编辑器区整体联动,状态保留。
  2. 分类树:多级展开/折叠、分类搜索过滤、右键新建子分类/重命名/删除(确认框 + N 提示)。
  3. 编辑器区:选中分类显示聚合项(含子孙);卡片/列表切换且重启保留;单击详情 / 双击启动 / 右键菜单;新增归当前分类;列表顶部搜索过滤。
  4. 详情表单:分类树形选择器;其余字段编辑即时保存(与现状一致)。
  5. 设置上下文:外观/热键/数据三分组,行为与 v0.1.2 一致;齿轮与 File→设置 切到设置上下文。
  6. 迁移:旧 launcher.json 首启自动转换,项与分类不丢;手写新格式 JSON 可识别;悬空 `categoryId` 归「未分类」。
  7. 浮层 / 每项热键 / 托盘 / 日志 / 状态栏回归不变。
  8. NativeAOT 单文件发布通过。

## Out of Scope

- 多分类(一个启动项属多个分类;slug id 数组已留余地,本次不做)
- 分类拖拽排序(右键菜单够用;拖拽重排顺延)
- 开机自启、命令面板(继续顺延)
- 分类节点图标(本次不做)
- 删除回收站 / 备份(删除确认框即可;JSON 可手写 diff 兜底)
