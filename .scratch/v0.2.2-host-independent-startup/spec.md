# v0.2.2 宿主独立启动规格

Status: ready-for-agent

> 版本: v0.2.2
> 对应 ADR: `docs/adr/000202-01-host-independent-startup.md`

## Problem Statement

三层拆分后，宿主与扩展主机在行为上仍是绑定的：宿主首启即拉起扩展主机、退出时杀掉其进程、崩溃 1 秒后自动拉起，看一眼宿主主窗口也会顺手拉起五区；且两端各扫一遍插件目录，同一份清单出现两份视图。想要“常驻干净”（只留托盘、呼出浮层、全局热键做开发调试或单宿主分发）的用户做不到，不拉五区就得不到一个安静的宿主；想要确认崩溃隔离的用户也测不出来——任何一端的退出都会被另一端掩盖。需要把启动解绑、把管辖拆清，让单跑与合体都是可验收的状态。

## Solution

宿主独立启动 + 插件分层代管：宿主只管常驻与独立插件，运行期 DLL 全权委托扩展主机；名单归宿主，执行分开。宿主首启不再拉起、不再顺手拉起、退出不再杀进程、崩溃不再自愈，仅经用户手动才与扩展主机相遇；宿主只收独立进程插件，编译期工具模块与运行期 DLL 插件只在扩展主机侧组装与加载；扩展主机是特殊容器，不进插件列表、不允许禁用；关闭五区窗口只是隐藏，进程保留秒显。

## User Stories

1. As 用户, I want 宿主首启只见宿主窗口（写清托盘与浮层常驻中、五区未启动）, so that 常驻干净可验证。
2. As 用户, I want 点开宿主主窗口不再顺手拉起五区, so that 看一眼配置不会污染常驻态。
3. As 用户, I want 经托盘“打开工作台”或宿主窗口按钮才拉起扩展主机, so that 合体是我的主动选择。
4. As 用户, I want 托盘左键只显宿主不拉起五区, so that 快捷入口不附带副作用。
5. As 用户, I want 退出宿主不再杀掉扩展主机进程, so that 两端生死独立。
6. As 用户, I want 扩展主机崩溃或退出后宿主仅提示已崩溃或已退出并记日志、不自动拉起, so that 隔离可观测。
7. As 用户, I want 宿主单跑时托盘与呼出浮层与全局热键全部可用, so that 常驻能力不依赖五区。
8. As 用户, I want 扩展主机双击可独立跑满五区与首个工具模块, so that 五区可脱离宿主验证。
9. As 用户, I want 关闭五区窗口只是隐藏（下次秒显）而非退出进程, so that 重开无等待。
10. As 用户, I want 真正退出扩展主机只走明确的杀进程动作, so that 隐藏与退出不混淆。
11. As 用户, I want 宿主侧只看到独立进程插件（运行期 DLL 置灰并提示需扩展主机）, so that 单宿主分发的边界清晰。
12. As 用户, I want 运行期 DLL 插件只在扩展主机的设置→插件中可管, so that 两边列表不打架。
13. As 用户, I want 扩展主机不在插件列表中出现且不允许禁用, so that 底座不会被误关。
14. As 框架主人, I want 插件发现与启用开关只有宿主一份事实来源, so that 两端视图永不脑裂。
15. As 框架主人, I want 扩展主机不再自扫目录、只接收宿主推过来的待装 DLL 名单, so that 代管等于执行、不代发现。
16. As 工具作者, I want 同一份清单在两端语义一致（字段与版本规则不变）, so that 接入只需学一次。
17. As 工具作者, I want 独立进程插件未声明的能力在注册阶段被拒绝, so that 越权可被拦截。
18. As 工具作者, I want 编译期工具模块零改动继续在扩展主机中运行, so that 历史资产不作废。
19. As 工具作者, I want 运行期 DLL 复用工具模块契约写法（由扩展主机代理转发搜索/设置/热键）, so that 富插件与编译期一致。
20. As 用户, I want 禁用某独立插件后其搜索源、设置节、热键立即从浮层消失, so that 禁用即生效。
21. As 用户, I want 独立插件崩溃仅该来源消失、其他来源与常驻能力不受影响, so that 故障被隔离。
22. As 开发者, I want 契约版本握手保持单线（不匹配拒绝并提示更新）, so that 演进可控。
23. As 用户, I want 宿主与扩展主机任一端崩溃后另一端不受影响且状态可从日志定位, so that 联调可诊断。

## Implementation Decisions

- **启动解绑**：宿主首启、显示主窗口、退出、扩展主机退出四条路径去耦合——首启不拉起且不自动隐藏，显示主窗口不附带拉起，退出不杀扩展主机进程，捕获到扩展主机退出仅做已崩溃标记、提示与日志，不做定时自愈；拉起与重启只由宿主窗口按钮与托盘新增的手动项触发。
- **手动入口**：宿主占位窗口摆着说明常驻态并保留打开与重启两个按钮；托盘右键新增打开与重启工作台两项捷径，左键行为收敛为仅显示宿主。
- **隐藏语义钉死**：五区窗口关闭等于隐藏，进程保留；真退出只走明确的进程终止动作，隐藏与退出在文案上区分。
- **分工**：宿主只接受独立进程插件（进程拉起加管道会话）；编译期工具模块与运行期 DLL 插件只在扩展主机侧组装与隔离加载；需即时运行环境的清单项在宿主侧置灰，判健康态的既有规则复用。
- **代管边界**：目录扫描、清单校验、启用持久化只留宿主一份；扩展主机去掉自扫，改为接收待装名单并按目录隔离加载、按模块标识与清单标识一致性校验后组装；清单字段、版本规则、契约版本不分叉。
- **身份**：扩展主机是特殊容器，不进入插件列表、不提供启用或禁用开关；宿主聚合搜索结果到呼出浮层仍为唯一聚合点，来源标记规则不变。
- **能力分级不变**：独立进程插件仅声明式三能力（搜索、设置节、热键），富插件可直接贡献五区；未声明即无，注册阶段拒绝越权。
- **一句话记忆**：独立插件生死宿主全权，运行期 DLL 生死扩展主机全权，运行期 DLL 看不看得见宿主说了算。

## Testing Decisions

- **好测试的标准**：只测外部行为——首启与显示主窗口是否拉起、退出是否杀进程、崩溃后是否自愈或仅标记、隐藏后进程是否保留、宿主侧清单过滤（运行期 DLL 是否置灰）、禁用后来源是否消失、越权注册是否拒绝、版本不匹配是否拒绝——不测窗口像素、管道帧格式与加载器内部。
- **单一高位缝**：沿用宿主测试工程为主缝，以内存直连的宿主服务端、记录式浮层、假工具模块与假搜索源、临时目录的发现与启用存储为驱动，无窗口、无子进程；五区组装测试保留为纯逻辑补充；启动器领域测试保持原位不碰。
  - 启动：断言首启与显示主窗口路径不再触发拉起；断言退出路径不再终止扩展主机；断言扩展主机退出后仅标记、不做自愈拉起。
  - 隐藏：断言五区关闭语义为隐藏而非退出。
  - 分工：断言宿主侧可加载集合不含运行期 DLL 且健康态为需扩展主机；断言扩展主机侧按名单加载成功、标识不一致或缺文件时失败但不影响其他项。
  - 隔离：断言独立来源消失后其余来源仍可搜；断言版本不匹配的注册被拒绝且搜索不包含其结果。
- **先前技艺**：组装测试的记录式浮层与假模块、故障隔离测试的内存客户端注册与注销、发现测试的临时目录隔离，均为本规格测试的直接先前技艺。

## Out of Scope

- 不新增插件能力种类，不改清单字段与契约版本。
- 不做插件热更新（运行期 DLL 变更仍需重启扩展主机），不做插件自动更新。
- 不改单实例锁、开机自启、关于对话框、主题体系与布局持久化。
- 不改搜索聚合 sıralama 与限流算法（沿用唯一聚合点既有策略）。
- 不做单宿主回退包的分发脚本变更，只定行为，不定 CI 流水线。

## Further Notes

- 本规格是三层拆分规格的启动与管辖补丁，与编译期组合、原生提前编译约束均保持兼容；术语沿用域词汇表（工具模块、独立插件、扩展主机、插件、呼出浮层）。
- 联调时若对“隐藏还是退出”有疑，先看进程在不在，再看日志中的退出与崩溃标记。
