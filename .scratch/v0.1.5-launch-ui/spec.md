# v0.1.5 启动上下文 UI 调整规格

Status: ready-for-agent

> 版本：v0.1.5
> 对应 ADR：`docs/adr/000105-01-launch-context-interaction-model.md`

## Problem Statement

启动上下文（分类树侧边栏 + 启动项列表 + 详情表单）的交互与视觉停留在「功能可用」层面：列表单击开详情、双击启动的手势难发现且两者冲突；悬停/选中/空状态反馈缺失，启动失败只能靠状态栏文字与输出面板；卡片信息过薄、详情表单 7 字段扁平无分区；主窗口列表键盘哑火，与键盘完备的呼出浮层手势分裂。v0.1.4 解决了三栏导航模型，本版本补齐「启动」操作本身的交互与视觉。

## Solution

以「列表即启动面」为核心统一手势：单击启动、双击防重、编辑退居右键与悬停按钮、键盘 ↑/↓+Enter 完整可用。补齐反馈：启动失败 toast+状态栏红字、空状态分场景引导、悬停/选中视觉区分。规整布局：卡片增强为图标+名称+命令同行小卡、详情页第一行工具行+基本/高级分组、详情标签动态显示项名，并统一「第一行=工具行」模式。

## User Stories

1. As a Launcher 用户, I want 单击列表中的启动项即启动它, so that 启动是最直接的操作。
2. As a Launcher 用户, I want 双击同一启动项不会重复启动两次, so that 快速双击不会造成误开。
3. As a Launcher 用户, I want 编辑入口通过右键菜单与悬停「编辑」按钮提供, so that 主操作保持简洁同时编辑仍可发现。
4. As a Launcher 用户, I want 列表支持 ↑/↓ 移动选中、Enter 启动选中项, so that 键盘可以完成完整启动路径。
5. As a Launcher 用户, I want 「/」或 Ctrl+F 聚焦列表搜索框, so that 键盘可快速过滤。
6. As a Launcher 用户, I want 悬停时列表项背景微亮, so that 我知道哪一项可交互。
7. As a Launcher 用户, I want 键盘选中项以 accent 高亮区分于悬停态, so that 键盘导航时焦点清晰可见。
8. As a Launcher 用户, I want 启动失败时弹出 toast 提示并在状态栏以红色显示, so that 失败不会被忽略。
9. As a Launcher 用户, I want 启动成功后不打扰(状态栏轻文字或静默), so that 成功是预期行为不产生噪音。
10. As a Launcher 用户, I want 空列表时看到「暂无启动项」并可直接新增, so that 空状态有下一步出口。
11. As a Launcher 用户, I want 搜索无结果时看到「清空搜索」动作, so that 我可以快速恢复列表。
12. As a Launcher 用户, I want 卡片显示图标+名称+命令且图标与名称同行, so that 卡片可扫读更多信息。
13. As a Launcher 用户, I want 详情页第一行为「启动/删除」工具行、字段按基本/高级分组, so that 测试启动不用滚到底、表单可扫读。
14. As a Launcher 用户, I want 详情标签动态显示当前项名, so that 多标签时能辨识对象。

## Implementation Decisions

- **手势模型**：列表项（卡片/列表）单击=启动；双击忽略（防重时间窗，避免单击启动后双击连开两次）；行尾「启动」按钮移除，改为悬停浮现的「编辑」按钮（卡片角落、列表行尾）；右键菜单保留「编辑/删除」；「在侧边栏定位」等既有机制不变。
- **键盘导航**：列表获得焦点后 ↑/↓ 移动选中、Enter 启动选中项、「/」或 Ctrl+F 聚焦搜索框；选中模型卡片/列表共用；选中态与悬停态视觉区分（悬停=背景微亮，选中=accent 背景+左缘 accent 条）。
- **启动反馈**：成功静默（状态栏轻文字或完全静默）；失败 toast + 状态栏红字，输出面板照记日志。
- **空状态**：分场景引导组件——「暂无启动项」→ 图标+文案+「＋新增启动项」按钮；「无匹配启动项」/「无匹配分类」→ 图标+文案+「清空搜索」；分类树侧边栏、列表共用一套组件。
- **卡片**：固定 ~170×96，24px 图标+名称同行，命令小字第二行。
- **列表行**：图标+名称/命令两行+行尾悬停「编辑」，不再有常驻按钮。
- **详情页**：第一行工具行（「启动」「删除启动项」）→「基本」分组（名称/命令/参数/工作目录/分类）+「高级」分组（图标/每项热键）；删除表单内名称/id 标题；详情标签动态显示当前项名（Workbench 增加「改文档标题」能力，基于 MewDock `DockPane.Title` 可写属性）。
- **工具行模式**：统一「第一行=工具行」——侧边栏=分类搜索框，启动项列表=搜索+新增+形态切换，详情页=启动/删除按钮。
- 实现遵守 ADR `000105-01` 与既有 MewDock、编译期组合及 NativeAOT 决策。

## Testing Decisions

- 最高且唯一的验收缝是 Launcher App 本身，沿用现有 Workbench/Launcher 功能通过示例工具验收的约定，不新建独立测试项目。
- 可纯逻辑化的部分（双击防重时间窗、选中模型、空状态判定）在现有 `tests/Mew.Launcher.Tests` 项目补 xunit 用例。
- 好测试只观察可见行为与持久化结果，不断言内部状态字段或 MewDock 调用顺序。
- 手工冒烟应覆盖：卡片/列表单击启动与双击防重；悬停「编辑」按钮在卡片角落与列表行尾的出现与点击；右键编辑/删除；↑/↓+Enter 键盘启动与 `/`/Ctrl+F 聚焦搜索框；悬停微亮与选中 accent 高亮的视觉区分；启动失败 toast+状态栏红字、成功静默；三种空状态（暂无启动项→新增、无匹配启动项→清空搜索、无匹配分类）的引导动作；卡片图标+名称同行与命令小字、列表行信息排布；详情页工具行「启动/删除」、基本/高级分组、标签动态显示项名；切换项时标签跟随变化。
- 验收同时确认既有分类树、搜索过滤、卡片/列表切换持久化、每项热键与呼出热键、在侧边栏定位未回归。

## Out of Scope

- 呼出浮层（OverlayWindow）的交互与视觉（搜索质量、鼠标悬停、结果数量等）。
- 设置页、标题栏、菜单栏、状态栏等 Workbench chrome 的调整。
- LauncherRunner 执行器能力（异步启动、进程跟踪、以管理员运行、环境变量、启动历史等）。
- 分类拖拽排序、多分类、开机自启、命令面板等 v0.1.3 顺延项。

## Further Notes

- 键盘选中模型与呼出浮层的循环选择（↑/↓ 环绕）同构，可抽同一套纯逻辑类供两处使用。
- 悬停/选中/空状态的颜色一律取自五区色板（编辑器区背景层级与 accent），不引入硬编码色值，保证亮暗主题下自动适配。
- 验收记录沿用 v0.1.3/v0.1.4 模式（自动化验证 + 人工冒烟清单），在实现完成后补写。
- 票据依赖：02 依赖 01（选中态与悬停态同层实现），04 依赖 01（悬停编辑按钮布局），03/05 无依赖，可并行。
