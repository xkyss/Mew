# v0.2.3 插件生命周期状态规格

Status: ready-for-agent

> 版本: v0.2.3
> 对应 ADR: `docs/adr/000203-01-plugin-lifecycle-states.md`

## Problem Statement

三层插件宿主（ADR-000201）与宿主独立启动（ADR-000202）落地后，插件生命周期语言仍含混：「卸载」一词同时压着 *uninstall*（移除）与 *unload*（运行态释放）两个概念，讨论与文档反复在「要不要启用/禁用、加载/卸载两对功能」上绕圈。更实质的裂缝在代码里：设置→插件面板只按 `enabled` 推「已启用/已禁用」标签，T2 禁用后本次会话仍加载着却显示「已禁用」——一句谎言；`plugins.json` 宿主与扩展主机两端都在写（扩展主机面板直接 `SetEnabled + Save`），违背 000202「单一事实来源」，并发写有竞争；`PluginHealth.Crashed/Disabled` 枚举存在却从不展示；宿主侧没有 T3 管理 UI，`src` 也尚无任何 T3 exe 拉起代码。需要把生命周期词汇、状态语义、崩溃归因与写权力一次钉死，让「设置→插件」行的标签与动作对用户诚实。

## Solution

按 VS Code 词法重新分层，一行一状态一动作：

- **安装/卸载（install/uninstall）= 存在性**：插件目录在扫描范围内即「已安装」；「卸载」专指 uninstall（移出受管范围）。v0.2.x 不设卸载按钮，目录增减已覆盖职责。
- **启用/禁用（enable/disable）= 参与策略**：持久化于 `plugins.json`（`{[id]: enabled}`，缺省启用）。
- **加载/卸载（load/unload）退出用户词汇**，退回引擎内部动词（T2 ALC 装载、T3 进程拉起/杀）；中文文档与 UI 用「回收/释放/拉起/杀掉」，不再用「卸载」指运行态释放。

禁用 = 停 + 回收，生效时机按隔离能力分型：**T3 禁用立即回收**（宿主杀进程，来源当场消失）；**T2 禁用意图先落、下次主界面启动不再装载**（不做运行时 ALC 卸载），行上副提示「重启扩展主机后生效」。崩溃按进程归因：**每插件行「已崩溃」只属 T3**（行内动作变「重启」，宿主重拉进程）；T2/T1 崩溃即扩展主机进程崩溃，恢复走宿主级「重启扩展主机」。崩溃态不落盘，宿主重启后按启用态正常拉起，仅运行期做防循环计数（启动后短时崩 N 次 → 本次不再自动拉起）。

`plugins.json` 写权力归一宿主：扩展主机面板开关不再自行 `Save()`，经 IPC 请求宿主落盘；T3 行 UI（状态/开关/重启）落在宿主侧，扩展主机面板收窄为 T1/T2。

## User Stories

1. As 用户, I want 设置→插件每个插件只显示一个状态词与一个动作（启用/禁用开关）, so that 不会出现「已启用未加载、已禁用仍加载」式的四态混乱。
2. As 用户, I want 健康且启用的插件行显示「已启用」、健康且禁用的显示「已禁用」, so that 参与策略一目了然。
3. As 用户, I want T2 DLL 插件被禁用且本次会话仍加载着时，行上不谎称已停、而提示「重启扩展主机后生效」, so that 行标签对用户诚实。
4. As 用户, I want 禁用 T3 独立插件后其搜索源、设置节、热键立即从宿主侧消失且进程被回收, so that 禁用即生效（兑现 v0.2.2 故事 20）。
5. As 用户, I want 禁用 T2 DLL 插件后意图落盘、下次主界面启动不再装载（不做运行时 ALC 卸载承诺）, so that 行为可预期、无 best-effort 谎言。
6. As 用户, I want 重新启用 T3 后宿主立即拉起进程、启用 T2 后经重启扩展主机装载, so that 启用路径与禁用对称且清楚。
7. As 用户, I want 已崩溃的插件行显示「已崩溃」且动作变为「重启」, so that 崩溃恢复不必先禁用再启用。
8. As 用户, I want 清单错误 / ID 重复 / 需 JIT 的插件行以健康态覆盖策略词并标红、不提供误导性开关, so that 无法正常参与的插件不会被假装可切换。
9. As 用户, I want 「卸载」一词只表示把插件目录移出受管范围（uninstall），v0.2.x 由目录增减承担、不设卸载按钮, so that 中文文档不再一词两义。
10. As 用户, I want T3 独立插件崩溃仅该来源消失、其余来源与常驻能力不受影响, so that 故障被隔离（沿用既有隔离语义）。
11. As 用户, I want T3 崩溃后点行内「重启」由宿主重新拉起该进程, so that 单插件可恢复。
12. As 用户, I want T2/T1 崩溃即扩展主机进程崩溃，宿主侧以「重启扩展主机」整体恢复、不制造「单个 T2 已崩溃」, so that 归因与恢复动作一致。
13. As 用户, I want 宿主重启后按启用态重新拉起插件（崩溃标记不落盘）, so that 一次性崩溃（休眠唤醒、手动杀、外部环境）不粘住下次启动。
14. As 用户, I want 同一插件启动后短时反复崩溃时宿主本次运行不再自动拉起（防循环）而标「已崩溃」待手动, so that 崩溃风暴不会无限重启。
15. As 框架主人, I want 崩溃标记只在运行期推导、不进 `plugins.json`, so that 持久化文件只存参与策略、无状态污染。
16. As 框架主人, I want `plugins.json` 只宿主一处写, so that 兑现 000202 单一事实来源、消除并发写竞争。
17. As 框架主人, I want 扩展主机面板的启用/禁用操作经 IPC 请求宿主落盘、宿主确认后刷新两侧, so that 双端视图永不脑裂。
18. As 框架主人, I want 扩展主机设置→插件列表只列 T1/T2（非 exe 行）, so that 职责按 ADR-000202 收敛、T3 不由扩展主机代管。
19. As 用户, I want T3 插件的状态/开关/重启 UI 在宿主侧可达（不依赖扩展主机活着）, so that 独立插件随时可管。
20. As 开发者, I want 生命周期相关行为有黑盒测试锁定（标签推导、禁用回收、崩溃归因、防循环、写权力）, so that 语义不随重构漂移。
21. As 文档读者, I want 词汇表与运行文档同步「卸载=uninstall、运行态写作回收/释放」, so that 后续文档不再用「卸载 ALC」式措辞。

## Implementation Decisions

- **词汇落盘**：术语写入域词汇表（CONTEXT.md 新增「插件启用/禁用」「插件安装/卸载」两词）与 `docs/run.md` 等运行文档；行为描述以 ADR-000203 为准。
- **行标签推导为纯逻辑**：从 `enabled`（策略）+ 健康态（`PluginHealth`）+ 崩溃集合（宿主运行期）+ 「本会话是否仍加载」（T2 实态）推导「显示词 + 动作」——`Healthy => enabled ? 已启用 : 已禁用`；`InvalidManifest/DuplicateId/NeedsJit` 健康态覆盖策略词并禁动作；T3 崩溃覆盖为「已崩溃 + 重启」。推导函数无 UI 依赖，可无头测试。
- **T2 诚实副提示**：行标签主词反映持久策略，但当「意图 ≠ 本会话实态」（本次仍加载）时附加「重启扩展主机后生效」副提示；不再只凭 `plugins.json` 谎报已停。
- **崩溃归因与防循环**：宿主维护崩溃集合（`_crashedPlugins` 语义保留）——T3 进程退出/IPC 断连 → 标该插件已崩溃，行动作变「重启」（重新拉起该 exe）；启动/拉起路径带运行期防循环计数（启动后短时崩 N 次 → 本次运行不再自动拉起），宿主重启即复位。
- **崩溃不落盘**：`plugins.json` 仍只存 `{[id]: enabled}`；崩溃态为运行期推导，宿主重启后按启用态重新拉起。
- **写权力归一**：扩展主机面板的开关处理不再本地 `SetEnabled + Save()`，改发 IPC 请求宿主落盘，宿主持久化成功后回推刷新；宿主为 `plugins.json` 唯一写者。
- **T3 生命周期接线**：宿主增加 exe 插件（`entry.type=exe` + `entry.path`）的拉起/杀/重启路径与探活；崩溃/断连统一走进程退出与 IPC 断开两条标记路径（对照宿主已有扩展主机进程管理先例）。T3 管理行 UI 落宿主侧（占位窗/托盘入口），扩展主机面板过滤掉 exe 行。
- **引擎动词保留**：加载器内部 `Load/Unload`（ALC）与进程拉起/杀为引擎动作，不暴露为用户词；T2 禁用 = 下次启动不装载（沿用加载器跳过禁用项逻辑），热更新语义不变。

## Testing Decisions

- **好测试的标准**：只测外部行为——行标签推导（策略 × 健康态 × 崩溃集合 × T2 实态）、T3 禁用触发回收且来源消失、崩溃后行标已崩溃且动作变重启、防循环达 N 次后不再自动拉起、宿主重启后崩溃标记复位并按启用态重拉、扩展主机开关走「请求宿主写」而非本地 `Save()`——不测窗口像素、管道帧格式与 ALC 内部。
- **单一高位缝**：宿主测试工程为唯一主缝（沿用 v0.2.1/v0.2.2 的单一缝纪律），以内存直连宿主服务端、假启用存储、假描述符、假崩溃集合驱动，无窗口、无子进程；标签推导为纯逻辑补充。
  - 标签：断言健康×启用×崩溃×T2 实态四维的显示词与动作推导正确、T2 副提示出现条件正确。
  - T3 禁用：断言 kill/回收路径被触发、来源从浮层消失。
  - 崩溃：断言进程退出/IPC 断连后行健康态为已崩溃、动作变重启；防循环计数达阈值后不再自动拉起；宿主重启（新实例）后标记复位并按启用态重拉。
  - 写权力：断言扩展主机侧开关触发的是「请求宿主落盘」而非本地 `Save()`。
- **先前技艺**：启用存储读写往返与默认启用、宿主侧可加载过滤（仅 exe）、断开标记为已崩溃、DLL 加载跳过禁用项等既有用例，均为本规格测试直接先前技艺。

## Out of Scope

- **不做卸载按钮/安装器**：「卸载」仅作词汇与存在性状态位，目录增减（设置页目录管理 + `MEW_PLUGINS_EXTRA`）已覆盖职责。
- **不做空闲内存卸载**：重 T3「保持已启用但不驻留、需要时才拉起」记 ADR-000203 Future，将来为宿主级单一策略开关，非每插件第二开关。
- 不改清单字段、契约版本、三层结构、宿主独立启动既有语义；不引入插件市场/自动更新/签名校验。
- 不做 T2 运行时 ALC 卸载（禁用 = 下次启动不再装载，语义已钉死）；不改隐藏/退出语义与扩展主机身份（特殊容器不进列表、不可禁用）。
