# 启动类型为推导维度,不落盘存储

用户需要区分显示「URL / 程序」类启动项。若把类型存为字段或标签,用户修改命令后类型仍指向旧值,产生与命令相悖的「第二真相」;而 `LauncherRunner`(URL 不带参数)与 `IconResolver`(URL 不提取图标)已有从命令推导 URL 的先例。故类型不新增字段,由命令在展示层推导(URL / 程序两档,脚本 .bat/.cmd 并入程序),仅用于徽标与类型过滤。

## Considered Options

- **存储 kind 字段(未选)**:item 增加显式类型字段。需要迁移与校验,且命令与字段双源不一致时无法判定谁对——撒谎字段。
- **推导(选定)**:从 Command 推导类型,命令是唯一事实来源,推导结果恒与命令一致;零存储、零迁移。

## Consequences

- 无新数据字段;类型推导为纯展示层逻辑,卡片/列表徽标与列表工具行类型过滤下拉消费同一推导函数。
- 将来若出现无法从命令推导的类型(如搜索模板 `{query}` 占位),再考虑引入存储字段,推导退为默认值。
