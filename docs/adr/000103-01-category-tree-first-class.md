# launcher.json 分类树独立实体(分类是一等公民)

v0.1.1/v0.1.2 的启动项分类是单字段自由字符串(`category: "开发"`),侧边栏平铺、活动栏按分类堆图标。v0.1.3 重新规划启动器,支持「全部 + 多级嵌套」分类,故将 `launcher.json` 重构为 `{ categories, items }`:分类树是一等公民(节点 = 全局唯一 slug id + 名称 + 子分类),启动项通过 `categoryId` 引用分类节点,移动/重命名分类不触碰任何启动项数据。选择独立树而非路径数组,因为多级嵌套下路径方案的重命名/移动要遍历改写所有 item、空分类与分类顺序无法表达;代价是 JSON 拆成两段、悬空引用需归一化(Load 时归入「未分类」)。

## Considered Options

- **路径数组(未选)**:`"category": ["游戏", "Steam"]`,分类树由所有 item 的路径聚合推导。手写 JSON 直观;但重命名/移动分类要遍历改所有 item(路径变一次 diff 刷屏)、空分类无法持久(没 item 就没节点)、分类顺序无字段;「全部」与父分类的聚合语义只能靠推导。
- **独立分类树 + slug id 引用(选定)**:树是一等公民,item 挂 `categoryId`(全局唯一 slug,如 `games-steam`,自动生成短 id、手写可自定义)。重命名/移动分类只改树;空分类/顺序/层级可持久化;悬空引用(指向已删分类)Load 时归「未分类」;「全部」= 根聚合、树底「未分类」= 无分类项聚合;未来"一个启动项多分类"可演进为 id 数组。

## Consequences

- `launcher.json` 结构变更:`{ "categories": [...], "items": [...] }`;旧平铺数组首启自动迁移(旧分类文本 → 根级分类,「默认」→ 未分类),无备份(用户决定,JSON 可手写 diff 兜底)。
- 删除分类 = 连根删(子分类与项全删),必须弹确认框(提示删除 N 个启动项);「全部」「未分类」是固定聚合节点,不可管理。
- 聚合语义:选中父分类显示其子树所有项;「全部」= 所有分类 + 未分类。
- 详情表单「分类」字段从文本框改为分类树选择器;一个启动项单分类(多分类留作未来演进)。
- 术语:`CONTEXT.md` 新增「分类」「未分类」;「启动项」定义补充"归属分类树节点"。
