# 单一主插件目录 + 链接开发目录

> **一句话定调：一个可修改的主目录承载全部插件（子目录 = 插件），开发期把构建输出以链接挂进主目录；多目录列表、优先级、`MEW_PLUGINS_EXTRA` 三套机制废除。**

多目录模型（`settings.pluginDirs` 列表 + 目录管理 UI + `MEW_PLUGINS_EXTRA` + 安装目录根）为「主目录可替换」的假想灵活性买单：目录节是插件设置页最复杂的一块（设为默认/至少保留一项/优先级文案），而真实使用证据显示复杂性买错了东西——宿主实际配置的第一项始终是用户目录本身（且该目录为空）、`MEW_PLUGINS_EXTRA` 从未配置、唯一的第三方插件 mxd 靠第二项自定义目录指向其构建输出。此外「第一项为默认目录」的文案与「env 目录永远排在最前」自相矛盾。用户的开发工作流（构建输出不复制、直接联调）应由文件系统原生的**链接**承担，而非目录列表机制。

## Considered Options

- **维持多目录现状**：零迁移成本，但复杂度服务的场景不存在，且 0.20 重做插件页时这些复杂度要原样搬一遍。→ 未选。
- **主目录固定 + 附加目录列表**：保留列表机制、只废除「默认」语义——比现状简单，但添加/删除/顺序/冲突说明一整套仍在。→ 未选。
- **砍 UI 只留 `MEW_PLUGINS_EXTRA`**：GUI 常驻宿主不继承 shell 环境，mxd 将无法加载，与真实用法正面冲突。→ 未选。
- **单一主目录 + 链接开发目录（选定）**：见下。

## 决策

1. **主目录唯一且可修改**：默认 `%APPDATA%\Mew\Plugins`，settings 单值 `pluginDir`；UI 提供文件夹选择器（MewUI 0.20 自带 `FileDialog`/`FolderDialogOptions`）修改，修改后提示重启宿主生效（重扫 IPC 另票）。
2. **主目录下子目录 = 插件**：发现逻辑不变（`<id>/plugin.json`），**链接子目录即开发通道**——实测现有枚举与文件穿透对 junction/symlink 原生可用（`GetDirectories` 枚举到链接项、穿透读 `plugin.json` 成功），零发现代码改动，以测试锁定；`mklink /D` 需开发者模式（可指 UNC/WSL 路径），`mklink /J` 免特权限本机卷。
3. **安装目录扫描根移除**：从未有内置插件内容（目录不存在），UI 锁定行随之消失；ADR 记录恢复路径（将来内置插件时恢复一个扫描根为小改动）。
4. **`MEW_PLUGINS_EXTRA` 移除**：链接工作流完全覆盖其场景且不依赖启动环境；配置源收敛为唯一。
5. **迁移**：`pluginDirs` 列表 → 单值 `pluginDir`（取列表首项，缺省用户目录）；被移除的附加目录写入宿主日志提示人工建链接——迁移代码不做文件系统特权操作（symlink 创建需要开发者模式/管理员）。
6. **卸载语义随之简化**：删除主目录下的插件子目录即卸载（ADR-000203「目录增减承担卸载」修订注记）；「卸载专指 uninstall、运行态回收不叫卸载」的词汇边界不变。

## Consequences

- `ResolvePluginRoots`、`GetExtraPluginDirs`、`settings.PluginDirs` 列表退役；settings schema 迁移沿用既有先例；两进程的发现接线同步收敛。
- 插件设置页目录节：三按钮/优先级文案/锁定行 → 单行主目录 + 修改按钮 + 链接说明；开发联调路径从「配置目录」变为「建一次链接」。
- ADR-000203 修订注记（卸载语义）；「默认目录」概念废除（未入词汇表，无 CONTEXT.md 改动）。
- 主目录修改后的生效仍依赖重启宿主——「重扫 IPC」断点保持独立票，不混入本版。
- 测试：链接扫描锁定（无头 symlink）、迁移往返、单根发现；文件夹选择器对话框为运行期行为，进 Windows 走查清单。

## Alternatives Rejected

- 见 Considered Options；多目录系（现状/附加列表/纯 env）均因复杂度与真实用法不匹配被放弃。
