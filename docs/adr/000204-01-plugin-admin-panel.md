# 插件管理面板：行管理收敛共享模块，两 adapter 坐实 seam

> **一句话定调：行渲染与动作路由只有一份，宿主给进程内 adapter、扩展主机给 IPC adapter；锁与校验门收进 adapter，锁顺序从注释升格为不变量。**

v0.2.3 把行标签契约钉在 `PluginRowState.Derive` 纯逻辑上（ADR-000203 第 6 条），但它的两个调用方——宿主占位窗的 T3 行与扩展主机设置→插件的 T2 行——各养一套近乎克隆的渲染与路由：行标题格式、健康态配色、动作按钮、校验文案两侧各写一份（字节级相同却无人守护，一处改动需两处同步）；两份内存态 `plugins.json` 副本各随其主；engine 锁 → enable 锁的取锁顺序只活在注释里。更实质的裂缝：IPC 路径（`OnPluginEnableSet`，线程池线程）写 `plugins.json` 完全无锁，与宿主 UI 动作路径（持启用锁）并发——真实无守卫交错点；扩展主机开关路径的管道读无超时，宿主挂起即冻结扩展主界面 UI。纯函数已经很深，真 bug 藏在「怎么调」里。

## Considered Options

- **只给 IPC 路径补一把锁（浅修）**：三行改动消除无锁写，但克隆渲染/路由、双副本、注释级锁顺序原样保留，下次动插件行仍要两处同步。→ 未选，治标。
- **两侧只共享数据、各自渲染**：收敛不彻底，克隆还在，文案/配色漂移照旧。→ 未选。
- **新建独立共享库工程**：当前只有这一个跨进程共享场景，撑不起一个 csproj。→ 未选。
- **共享插件管理面板 + 两个 adapter（选定）**：见下。

## 决策

1. **共享模块 `PluginAdminPanel` 落 `Mew.Workbench`**（宿主与扩展主机的公共层，已承载五区/浮层 UI 代码）。interface 只有两个动作：`Snapshot()` → 行视图模型集合（描述符 + `PluginRowState` + 校验错误），`Apply(id, action)` → 结果。渲染器进程无关：行标题格式、警示配色、单动作按钮、校验文案、Hint（非空才渲染）只此一份；行序统一按 id 排序（对 v0.2.3 的唯一 UX 豁免——原扩展主机侧为发现顺序）。
2. **两个 adapter 坐实 seam**（两个真实 adapter = 真实 seam，非假想需求）：宿主进程内 adapter 包生命周期引擎 + `plugins.json`——engine 锁与启用锁全部收进 adapter 内部，engine 锁 → 启用锁单向取锁升格为实现不变量，adapter 之外任何调用者不接触锁；unknown-id / 保留 id 拒绝门收敛于此。扩展主机 adapter 包发现结果 + 本地只读启用缓存 + DLL 装载实载集合，写走 `pluginEnableSet` 一次性 IPC。
3. **IPC one-shot 处理器改走 adapter 同一条加锁路径**：`OnPluginEnableSet` 不再自行读写 `plugins.json`，消除线程池无锁写与 UI 动作路径的并发交错；ack 报文映射留在 IPC 消息层，adapter 不感知报文形状。
4. **本地启用缓存角色钉死**：扩展主机侧缓存 = 启动读盘（供 DLL 装载跳过禁用项）+ ack 成功后内存同步，永不本地 `Save()`——「宿主唯一写者」（ADR-000203 第 7 条）原样兑现，只是收进 adapter。
5. **扩展主机开关路径加 2s 读超时**，与连接超时对称；「宿主接受连接后不回话即冻结扩展主界面」的隐患一并消除，超时按宿主不可达处理。
6. **零 UX 回归**：行文案、行标签契约（策略单标签 + 健康态覆盖）、按钮语义、警示配色严格保持 v0.2.3；面板级内容（打开/重启主界面、退出主界面进程、页脚说明）不进共享模块，留各自 exe；宿主列 T3、扩展主机列 DLL 行的分工不动（ADR-000203 第 7 条；T1 已摘除，注释过时称谓顺手清理）。
7. **分两步落地**：先共享模块 + 宿主切换（顺带验证 AOT 发布无反射/裁剪坑），再切扩展主机面板；每步可独立验收、可回退。

## Consequences

- 宿主侧行区块构建/刷新/动作路由（`BuildHostPlaceholder` 行区、`RefreshHostPluginRows`、`ApplyHostPluginAction`、`IsPluginEnabledLocked`）与扩展主机侧行区块（`RefreshPluginPanel` 行区、`TogglePluginEnabled`）收敛删除，两个 exe 各只剩 adapter 接线与面板级内容。
- 渲染、动作路由、锁顺序、unknown-id 门首次可测：宿主测试工程以无头控件树断言渲染（先例：组合测试的 `IntPtr.Zero` 组装 + Label/颜色断言），以 fake adapter 断言路由与锁顺序。
- 词汇：CONTEXT.md 新增「插件管理面板」词条；「插件页/T3 UI/插件列表」式散称退出文档。
- 本 ADR 是 ADR-000203 的**实现收敛补丁**：不推翻三层结构（000201）、宿主独立启动（000202）、生命周期词汇与写权力（000203）；行标签契约原样引用 000203 第 6 条。
- IPC 传输层其余问题（字符串嗅探分发、长连接双读者竞争、T3 搜索断头路）不在本 ADR 范围，归架构走查候选 2 另案。

## Alternatives Rejected

- 见 Considered Options；浅修与半收敛两案均因「克隆与注释级锁规则仍在」被放弃。
