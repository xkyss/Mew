# 启动项多分类:一个启动项可归属多个分类节点

v0.1.3 起启动项单分类(`CategoryId` 单值引用分类树节点),v0.1.5 迭代中发现真实需求:一个启动项应能在多个分类标题下找到(如一个游戏既属「游戏」又属「Steam」)。最初考虑把「分类」改名为「标签」以支持松散多归属,经论证分类树保留、改为树内多挂——`CategoryId` 演进为 `CategoryIds` slug id 数组,空数组 = 未分类。这是 ADR `000103-01` 预留的演进路径(原文:「未来一个启动项多分类可演进为 id 数组」);顺带把「URL / 程序」这类启动项类型拆出为推导维度,见 ADR `000106-02`。

## Considered Options

- **扁平标签替代分类(未选)**:把分类树打平成标签列表,一个项多个标签。丢失多级层级、父分类子树聚合、「未分类」收尾等结构语义;「游戏 / Steam」这类组织需求本是树节点,打平后无结构可依;若保留树另加标签则是与树并行的第二组织维度,双轨制、心智更重。
- **树内多挂(选定)**:分类树保持一等公民,启动项从单值 `CategoryId` 改为数组 `CategoryIds`(空数组 = 未分类);侧边栏树中启动项出现在其所属每个节点下,父分类子树聚合语义不变。

## Consequences

- `launcher.json` 结构:item 的 `categoryId` 单值 → `categoryIds` 数组;手写 JSON 缺省 null 由数据层归一为空数组(沿用 Children 的归一模式)。迁移:旧单值 → `[id]`,null → `[]`;v0.1.3 的旧平铺格式迁移链不变。
- **删除分类语义改变**:从「连根删(连带删除启动项)」改为「摘除归属,永不删项」——从所有引用它的项上摘掉该 id;项还有其他归属则保留,一个不剩则归未分类;子分类随父分类整棵子树一并摘除;确认框文案从「将删除 N 个启动项」改为「N 个启动项将失去分类 X」。
- 详情表单分类字段从树形单选改为平铺多选(checkbox + 路径前缀,复用 `FlattenCategoryOptions`);「未分类」不再是可勾选项,改为「全不勾选 = 未分类」的隐式状态;勾选父分类不自动勾选子分类。
- 「在侧边栏定位当前启动项」:多归属下定位到树中顺序第一个所属分类节点,行为确定可测。
- 新建启动项:在分类节点下新建 → 初始归属数组含该节点;在「全部」/「未分类」下新建 → 空数组。
- 术语:CONTEXT.md 更新「启动项」「分类」「未分类」定义(多归属、空归属数组),新增「启动类型」。
